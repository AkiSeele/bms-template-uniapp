# ble-disconnect-reconnect-prompt

## Goal

当蓝牙连接非正常断开（如信号丢失、电池物理断电、遥测超时等）时，向用户弹出全局对话框，提示“蓝牙已断开”，并询问用户是否启动重连。若用户确认，则自动发起重连逻辑并展示重连状态。

## Requirements

1. **断开状态监听与判定**：
   - 监听蓝牙连接断开事件（通过蓝牙服务层 `ble-manager.ts` 或 `bleStore` 状态变化）。
   - 区分用户“主动断开”与“非正常被动断开”。仅在非正常被动断开时触发重连提示。

2. **全局 UI 交互**：
   - 使用 `wot-ui` 的弹窗交互（如调用 `useDialog()`），确认框包含“取消”和“重连”按钮。
   - 页面必须显式挂载对应的 `<wd-dialog />` 与 `<wd-toast />` 以免弹窗失效（符合 wot-ui v2 开发规范）。
   - 弹出对话框前启用遮罩防连点。

3. **重连执行机制**：
   - 用户确认重连后，自动调用蓝牙连接 API。
   - 在重连执行中显示 Loading 状态（“正在重连...”），必须配合 `try-catch-finally` 并在 `finally` 中关闭 Loading，避免死锁。
   - 限制最大重连尝试次数或超时时间，超时未成功则提示“重连失败”。

4. **i18n 国际化要求**：
   - 弹窗和提示中的所有中文字符（如：“蓝牙已断开”、“是否重新连接？”、“正在重新连接...”、“重连成功”、“连接失败”）绝对禁止硬编码。
   - 所有文本必须归口到 `locale/zh-Hans.json`、`locale/zh-Hant.json`、`locale/en.json` 的 `"bms.reconnect.*"` 命名空间中。

5. **多端自适应兼容**：
   - 在微信小程序、Android、iOS 和鸿蒙端均需保持一致表现，没有未捕获的报错。

## Acceptance Criteria

- [ ] 蓝牙物理/异常断开后，可以自动感知并准确弹出确认重连的 `wd-dialog` 对话框。
- [ ] 确认重连时，会显示“重连中...”的 Loading 状态。
- [ ] 若重连成功，提示“重连成功”并恢复遥测主动轮询；若失败，提示“重连失败”。
- [ ] 切换系统语言（简体、繁体、英文）时，弹窗和提示文本完美自适应，没有遗留硬编码中文。
- [ ] 代码通过 `npx tsc --noEmit` 校验，无新增编译报错。
- [ ] 运行 `npx @wot-ui/cli lint` 无组件使用违规。

## Notes

- 蓝牙管理器可能需要暴露一个断开状态的 Event Emitter 或通过 Pinia Store 进行全局订阅。
